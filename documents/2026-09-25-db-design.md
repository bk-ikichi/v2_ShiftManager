# シフト管理アプリ v2 DB設計

作成日：2026-09-25
対象仕様：`documents/2026-09-25-shift-manager-v2-spec.md`
DDLの正本：`src/main/resources/db/migration/V1__init.sql`（Plan 1 Task 1で作成）

## 方針

- PostgreSQL 17（本番はNeon、ローカルはDocker）。マイグレーションはFlyway
- 時刻は `TIME`、日付は `DATE`、記録日時は `TIMESTAMPTZ`
- 時刻の制約（8:00〜23:00、30分刻み、開始 < 終了）はアプリ側とDBのCHECK制約の両方で守る
- 物理削除は「ポジション（未使用時のみ）」「パターン」「申請」「下書き中のシフト」に限る。スタッフは無効化のみ
- 店舗の概念は持たない（1店舗専用）

## テーブル一覧

| テーブル | 役割 |
|---|---|
| positions | ポジション（名前・表示順・非表示） |
| users | スタッフ（管理者を含む） |
| app_settings | アプリ設定（1行のみ。締切日数） |
| shift_patterns | スタッフ個人の申請パターン |
| shift_requests | シフト希望の申請（1人1日1件） |
| cycle_unavailable | 「この期間は出勤できない」チェック（1人1サイクル1件） |
| shifts | 確定シフト（1人1日1件）。どのポジション枠に入れたかを持つ |
| published_dates | 公開済みの日付 |
| shift_changes | 公開後の変更マーク（「変更あり」）。確認済みになるまで表示 |

## ER概要

```
positions 1 ─── * users            (users.position_id：初期ポジション。NULL可)
positions 1 ─── * shifts           (shifts.position_id：その日に入れた枠。必須)
users     1 ─── * shift_patterns
users     1 ─── * shift_requests   (user_id, work_date) 一意
users     1 ─── * cycle_unavailable(user_id, cycle_start) 主キー
users     1 ─── * shifts           (work_date, user_id) 一意
users     1 ─── * shift_changes    未確認分は (user_id, work_date) 一意
published_dates                    work_date 主キー（shiftsとは日付で対応）
```

## テーブル定義

### positions

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGSERIAL | PK | |
| name | VARCHAR(30) | NOT NULL | 例：社員、キッチン、カウンター |
| display_order | INT | NOT NULL | 転記画面・日別一覧の上からの並び順（昇順） |
| hidden | BOOLEAN | NOT NULL DEFAULT FALSE | 使用中で削除できないものを非表示にする |
| color | VARCHAR(20) | NOT NULL DEFAULT 'gray' | バーの色（`util/BarColor` のキー：sky・pink・red・orange・yellow・purple・blue・gray） |
| created_at | TIMESTAMPTZ | NOT NULL | |

### users

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGSERIAL | PK | |
| login_id | VARCHAR(50) | NOT NULL UNIQUE | 半角英数字と `-_.`、3〜50文字 |
| name | VARCHAR(50) | NOT NULL | 表示名 |
| password_hash | VARCHAR(100) | NOT NULL | BCrypt |
| position_id | BIGINT | FK positions, NULL可 | 初期ポジション。転記画面の名前候補の並び順に使う |
| admin | BOOLEAN | NOT NULL | 管理者権限 |
| enabled | BOOLEAN | NOT NULL | 無効化でログイン不可 |
| must_change_password | BOOLEAN | NOT NULL | 初回または管理者リセット後に変更を強制 |
| created_at / updated_at | TIMESTAMPTZ | NOT NULL | |

### app_settings

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| id | INT | PK、CHECK (id = 1) | 常に1行 |
| deadline_days_before | INT | NOT NULL、0〜30 | 締切＝サイクル開始日の何日前か。初期値5 |

### shift_patterns

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGSERIAL | PK | |
| user_id | BIGINT | FK users ON DELETE CASCADE | |
| name | VARCHAR(20) | NOT NULL | 例：朝、夕方 |
| start_time / end_time | TIME | NOT NULL、時刻CHECK | |

### shift_requests

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGSERIAL | PK | |
| user_id | BIGINT | FK users | |
| work_date | DATE | NOT NULL | |
| start_time / end_time | TIME | NOT NULL、時刻CHECK | 申請IN/OUT |
| note | VARCHAR(200) | NULL可 | 備考 |
| updated_at | TIMESTAMPTZ | NOT NULL | |
| | | UNIQUE (user_id, work_date) | 1日1時間帯 |

- 申請がない日は行を持たない
- サイクルの提出済み判定：そのサイクル内に1行以上ある、または `cycle_unavailable` に行がある

### cycle_unavailable

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| user_id | BIGINT | FK users、PK | |
| cycle_start | DATE | PK | サイクル開始日（1日・11日・21日） |

- チェックが入っているサイクルに申請行があってはならない（アプリ側で検証）

### shifts

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGSERIAL | PK | |
| work_date | DATE | NOT NULL | |
| user_id | BIGINT | FK users | |
| position_id | BIGINT | FK positions、NOT NULL | その日に入れた枠 |
| start_time / end_time | TIME | NOT NULL、時刻CHECK | IN/OUT |
| created_at / updated_at | TIMESTAMPTZ | NOT NULL | |
| | | UNIQUE (work_date, user_id) | 同一日の二重登録防止 |

- 下書きか公開済みかは `published_dates` に日付があるかで決まる
- 並び順は保持しない。表示時にポジションの表示順 → IN の昇順で並べる

### published_dates

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| work_date | DATE | PK | 公開済みの日 |
| published_at | TIMESTAMPTZ | NOT NULL | |

- 公開の取り消し機能はないため、行は追加のみ

### shift_changes

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGSERIAL | PK | |
| user_id | BIGINT | FK users | |
| work_date | DATE | NOT NULL | |
| change_type | VARCHAR(10) | CHECK IN ('ADDED','UPDATED','CANCELLED') | 追加・時刻変更・取り消し |
| created_at | TIMESTAMPTZ | NOT NULL | |
| acknowledged_at | TIMESTAMPTZ | NULL可 | スタッフが「確認済み」を押した日時 |

- 部分一意インデックス：`(user_id, work_date) WHERE acknowledged_at IS NULL`。未確認の変更は1人1日1件で、新しい変更が来たら置き換える
- 記録するのは公開済みの日の変更だけ。初回公開は変更扱いにしない
- 種別は登録前後のシフトで決める：前なし・後あり → ADDED、前あり・後なし → CANCELLED、前後あり かつ IN/OUTまたは枠が異なる → UPDATED、差分なし → 記録しない
- 未確認の変更が既にある場合は、それを削除して新しい種別で置き換える

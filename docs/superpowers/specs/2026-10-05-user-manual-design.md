# 取扱説明書（ヘルプ画面・PDF） 設計書

作成日：2026-10-05

## 目的

初めて使う人が迷わず使い始められるように、スタッフ用と管理者用の取扱説明書を用意する。アプリ内のヘルプ画面として読めるようにし、同じ内容のPDFをアプリからダウンロードできるようにする。

## 決定事項

| 項目 | 決定内容 |
|---|---|
| 種類 | スタッフ用・管理者用の2種類 |
| 原稿 | アプリ内のヘルプ画面（Thymeleaf）を正本とする。PDFはヘルプ画面を印刷用CSSでA4出力したもの |
| 画面の画像 | 載せる。デモデータで起動したアプリを自動で撮影する |
| 閲覧範囲 | スタッフ用はログインした全員。管理者用は管理者のみ |
| PDFの配布 | アプリからのダウンロードのみ。リポジトリの `documents/` 等には置かない |
| 作り直し | `npm run manual` 1回で画像とPDFをまとめて作り直す |
| 運用ルール | 店舗独自の追記はなし。仕様書の内容をもとに書く |

## 画面と配置

| 項目 | スタッフ用 | 管理者用 |
|---|---|---|
| ヘルプ画面 | `/help` | `/admin/help` |
| 見られる人 | ログインした全員 | 管理者のみ（既存の `/admin/**` の制限による） |
| PDF | `/manual/staff.pdf` | `/admin/manual/admin.pdf` |
| 画像 | `/manual/images/*.png` | `/admin/manual/images/*.png` |

- ヘッダーのメニューに「使い方」（`/help`）を追加する。マイページの隣に置く
- `/help` の先頭には、管理者にだけ「管理者向けの使い方」（`/admin/help`）へのリンクを出す
- ヘルプ画面は、先頭に「PDFをダウンロード」ボタン、続けて目次（章へのページ内リンク）、章ごとの本文の順に並べる
- 1つの手順は「画像 → 番号付きの手順 → 注意点」の形で書く
- 管理者用の冒頭に「申請やシフトの閲覧はスタッフ用を参照」と書き、内容を重複させない
- PDF・画像は `src/main/resources/static/` 配下に置く。`SecurityConfig.STATIC_RESOURCES` に含めないため、ログインしないと取得できず、`/admin/` 配下はスタッフには取得できない。配信用のコントローラーは作らない
- `/help` と `/admin/help` はController（`HelpController`）でテンプレートを返すだけとし、Serviceは作らない（業務ロジックがないため）

### 印刷用CSS

- `@media print` でヘッダー・メニュー・「PDFをダウンロード」ボタンを非表示にする
- 章ごとに改ページする。画像の途中で改ページしない
- A4縦。画像は紙の幅に収まるよう縮小する（スタッフ用のスマホ画像は幅を抑えて中央寄せ）

## 画像とPDFの作り方

`npm run manual` で `scripts/manual/build.mjs` を実行する。手順は次のとおり。

1. composeのPostgreSQLに、説明書専用のDB `shiftmanager_manual` を削除して作り直す（普段の開発DB `shiftmanager` には触れない）
2. そのDBに接続してアプリをポート8081で起動し、起動完了を待つ。Flywayがテーブルを作り、初期管理者 `admin` が作られる
3. `scripts/manual/demo-data.sql` でデモデータを入れる
4. Playwright（`playwright-core`）でPCにインストール済みのEdgeを起動し、ログインして各画面を撮影する
   - スタッフ用：スマホ幅（390×844、デバイスピクセル比2）
   - 管理者用：PC幅（1280×800）
   - 撮影は空のプロフィールで起動した別のEdgeで行う。普段のEdgeのアカウントや拡張機能は使わない
5. `/help` と `/admin/help` をA4のPDFに出力し、`static/` 配下に保存する
6. アプリを停止する（失敗した場合も停止する）

### デモデータ

- 架空のスタッフ5〜6人（例：山田 花子）と管理者2人、ポジション3つ（色付き）、申請パターン、申請、転記・公開済みのシフト、「変更あり」の記録を入れる
- 日付は実行した日からの相対で作る（例：今日の3日後にシフト）。締切やカレンダーが常にそれらしく見える代わりに、実行するたびに画像の日付は変わる。アプリに「今日を固定する設定」は追加しない
- 初期管理者 `admin` は名前を変え、パスワード変更の強制を外す。パスワードはPostgreSQLの `pgcrypto`（`crypt(..., gen_salt('bf'))`）でBCryptのハッシュを作る
- 初回ログインのパスワード変更画面を撮影するため、パスワード変更が必須のスタッフを1人入れる
- デモデータのパスワードはスクリプト内に固定で書く（説明書専用DBでしか使わないため）

### 前提・制約

- 実行にはDocker Desktop（composeのDBが起動していること）・Edge・Nodeが必要。手元のPC専用の作業で、本番（Render）やテストでは実行しない
- 追加する依存は開発用の `playwright-core` のみ（ブラウザ本体はダウンロードしない）。Javaの依存は増えない
- 生成した画像とPDFはコミットする
- 画面を変えたら `npm run manual` を実行し直す。CLAUDE.mdにこのルールを1行追加する

## 目次

### スタッフ用

1. はじめに：ログイン、初回のパスワード変更、ログイン状態の保持、ホーム画面への追加
2. トップ画面の見方：変更あり（確認済みの押し方）、次回の出勤、カレンダー、締切の案内、勤務予定時間
3. シフト希望を出す：サイクルと締切のしくみ、月ごとの入力と「登録する」、「この期間は出勤できない」、締切後に変えたいとき（管理者に伝える）
4. パターンを作る：マイページでの作成・編集・削除と、申請での使い方
5. 確定シフトを見る：日別シフト一覧（ガントチャート）の見方、見られる日の範囲
6. 困ったとき：パスワードを忘れた、シフトが表示されない など

### 管理者用

1. 最初にやること：`admin` での初回ログイン → ポジション登録 → スタッフ登録 → 締切日数の確認
2. ポジション管理：追加・色・並び順・非表示
3. スタッフ管理：登録（初期パスワードの省略）、編集、パスワードリセット（仮パスワードは1回しか表示されない）、無効化
4. 申請の確認：申請一覧の見方、未提出者、代理編集
5. シフトの転記：画面の見方、名前の選び方、警告の意味、行の追加、登録
6. 公開：この日を公開、期間を指定して公開、公開後の修正と「変更あり」
7. 設定：締切日数
8. 困ったとき：スタッフがパスワードを忘れた、退職者が出た など

## テスト

既存のControllerテスト（MockMvc）と同じ形で次を確認する。

- スタッフ・管理者とも `/help` を表示できる。管理者向けリンクは管理者にだけ出る
- 管理者は `/admin/help` を表示でき、スタッフは403になる
- `/manual/staff.pdf` はログインしたユーザーが取得でき、未ログインではログイン画面へリダイレクトされる
- `/admin/manual/admin.pdf` は管理者のみ取得でき、スタッフは403になる
- ヘッダーに「使い方」のリンクがある

`scripts/manual/build.mjs` 自体の自動テストは書かない。実行して画像とPDFの中身を目で確認する。
